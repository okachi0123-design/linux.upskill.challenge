## Today's Theme
Deeper into repositories — APT リポジトリの仕組み、`apt-cache` でのパッケージ調査、追加リポジトリ（universe / PPA）の扱い

## What I Learned
- APT の設定ファイルは `/etc/apt/sources.list` と `/etc/apt/sources.list.d/*.sources` に分かれる
- Ubuntu 24.04 (noble) では新形式（deb822 形式）の `ubuntu.sources` が使われており、`/etc/apt/sources.list` は空
- 旧形式（one-line）は `deb URL Suite Components...` の 1 行記述、新形式は `Types:` / `URIs:` / `Suites:` / `Components:` / `Signed-By:` のキー : 値形式
- 新形式の利点は、複数の Suite を 1 ブロックにまとめられること（`noble noble-updates noble-backports` を 1 行に書ける）
- Components は `main` / `restricted` / `universe` / `multiverse` の 4 種類で、Ubuntu 24.04 ではデフォルトで全部有効
- `apt-cache` はインストールせずにパッケージ情報を調べるコマンド
  - `pkgnames`: 利用可能なパッケージ名の一覧
  - `show`: パッケージの詳細情報（バージョン、依存関係、説明など）
  - `depends`: そのパッケージが依存している（forward）パッケージ
  - `rdepends`: そのパッケージに依存している（reverse）パッケージ
- **仮想パッケージ (virtual package)** という概念を学んだ
  - `apache` は実体のない「purely virtual」なパッケージで、`apt-cache show apache` ではバージョン情報が取れない
  - 実体は `apache2` で、こちらは正常に詳細が表示される
- `apt-cache depends` の出力にある依存の種類
  - `PreDepends:` インストール前に必須
  - `Depends:` 動作に必須
  - `Recommends:` 強く推奨
  - `Suggests:` 任意（関連ツール）
  - `|`（縦棒）は OR 条件を表す（どれか 1 つあれば良い）
- `apt-cache rdepends apache2` を実行すると、apache2 に依存する大量の Web アプリ（WordPress、MediaWiki、OpenStack 関連、phpPgAdmin など）が表示され、apache2 が Web サーバー基盤として広く使われていることが実感できた
- `add-apt-repository universe` はすでに有効なコンポーネントを再指定しても問題なく、内部で `apt update` が走る
- PPA（Personal Package Archive）は launchpad.net 上の個人リポジトリ。`ppa:<user>/<name>` 形式で指定する
- PPA は消えることがある（今回 `ppa:dawidd081/neofetch` が `not found` で追加できなかった）
- PPA を追加する前にメンテナンス状況や対応バージョンを確認することが重要

## Commands Used
```bash
# リポジトリ設定ファイルを確認
sudo vim /etc/apt/sources.list                      # 旧形式の設定ファイル（noble では空）
sudo vim /etc/apt/sources.list.d/ubuntu.sources     # 新形式（deb822）の設定ファイル

# パッケージ情報の調査（apt-cache）
sudo apt-cache pkgnames                             # 利用可能なパッケージ名を全部表示
sudo apt-cache show apache                          # 仮想パッケージ（実体なし → エラー）
sudo apt-cache show apache2                         # 実体パッケージ apache2 の詳細
sudo apt-cache depends apache2                      # apache2 が依存しているパッケージ
sudo apt-cache rdepends apache2                     # apache2 に依存しているパッケージ（逆引き）

# リポジトリの追加
sudo add-apt-repository universe                    # universe コンポーネント追加（既に有効）
sudo add-apt-repository ppa:dawidd081/neofetch      # PPA 追加（→ not found エラー）

# 履歴確認
history
```

## Where I Got Stuck
- `sudo apt-cache show apache` で `Can't select versions from package 'apache' as it is purely virtual` と表示された
  → 解決: `apache` は仮想パッケージで実体がないと分かった。実体である `apache2` を指定すれば情報が取得できる

- `sudo add-apt-repository ppa:dawidd081/neofetch` で `ERROR: ppa 'dawidd081/neofetch' not found (use --login if private)` が発生
  → 解決: 動画で紹介されていた PPA がすでに launchpad.net から削除されていた。PPA は永続的ではなく、メンテナーの判断で消えることがあると理解した。今回は PPA 追加自体はスキップして、コマンドの動作と仕組みの理解にとどめた

- `sudo add-apt-repository universe` を実行しても新しく追加されなかった
  → 解決: `ubuntu.sources` の `Components:` 行にすでに `universe` が含まれていたため、実質的には `apt update` のみが実行された

## Insights & Reflections
- ppaは規格がない個人のリポジトリをダウンロードするので、危ない可能性もある
- 今回出てきたppaはlaunchpad.netというみんなが個人のリポジトリを置けるコミュニティのものであった
