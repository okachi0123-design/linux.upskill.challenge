## What I Learned
- SFTPはSSHプロトコル上で動くファイル転送機能で、独立したプロトコルではない
- FileZillaはSFTP/FTP/FTPSをGUIで操作できるクライアントソフト
- VirtualBoxのNAT構成では、ホストポートをゲストポート22に転送して接続する
- WSL2の127.0.0.1はWindowsホストの127.0.0.1とは別物（WSL自身を指す）
- WSL2で`networkingMode=mirrored`を設定するとWindowsとネットワークを共有できる
- rsyncは差分転送するため2回目以降は変更分のみ送る（scpは毎回全部送る）
- rsyncの送信元末尾の`/`の有無で挙動が変わる：`/`ありは「中身」、なしは「フォルダごと」
- `rsync user@host:path local_path` ならダウンロード、`rsync local_path user@host:path` ならアップロード（コロンの位置で方向が決まる）
- `-u`オプションは送信先のmtimeが新しい時にスキップする「上書き保護」機能
- `-c`オプションはチェックサムで中身を比較する
- `-n`（--dry-run）で実行せずに動作だけ確認できる

## Commands Used

```bash
# WSLミラーモード設定（Windows側のPowerShellで実行）
notepad $env:USERPROFILE\.wslconfig
# 中身: [wsl2] / networkingMode=mirrored
wsl --shutdown

# rsyncでVMからダウンロード（バックアップ同期）
mkdir -p ~/vm_backup
rsync -avh -e "ssh -p <port>" <user>@127.0.0.1:/etc/ssh/ ~/vm_backup/ssh_config/
ls -la ~/vm_backup/ssh_config/

# テスト用ファイルの作成
mkdir -p ~/test_upload
echo "Hello from WSL" > ~/test_upload/hello.txt
echo "Day 12 upload test" > ~/test_upload/day12.txt
echo "rsync practice" > ~/test_upload/practice.txt
ls -la ~/test_upload/

# rsyncでVMへアップロード
rsync -e "ssh -p <port>" -rav ~/test_upload/ <user>@127.0.0.1:~/images/

# 差分転送の確認（新規ファイル追加 → 再rsync）
touch test_upload/another-file
rsync -avh -e "ssh -p <port>" ~/test_upload/ <user>@127.0.0.1:~/images/

# rsyncのオプション組み合わせ例
# -a: アーカイブ（権限・タイムスタンプ保持）
# -v: 詳細表示
# -h: 人間が読みやすいサイズ表示
# -n: dry-run（実行せず確認）
# -u: 送信先が新しいなら守る
# -c: チェックサムで中身比較
# --delete: 送信元にないファイルを送信先からも削除
```

## Where I Got Stuck
**問題1**: WSL2から `ssh-copy-id -p <port> <user>@127.0.0.1` で `Connection refused`
→ WSL2の127.0.0.1がWindowsホストのそれと別物だったため。`.wslconfig`に`networkingMode=mirrored`を設定して解決。
